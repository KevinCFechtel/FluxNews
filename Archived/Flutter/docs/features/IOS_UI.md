# Flux News iOS UI

Detailed implementation context for the iOS Liquid Glass application shell, adaptive layouts, settings, context actions, and acceptance criteria.

## iOS Liquid Glass App UI

- Status: initial implementation completed on 2026-08-05. This section concerns the main Flutter app UI, not the native WidgetKit widgets above. Real-device visual, accessibility, and performance profiling is still required before release.
- The implementation pins `liquid_glass_widgets` to `0.29.2`, initializes and wraps it only on iOS in `lib/main.dart`, and explicitly uses `GlassQuality.standard`. Android continues through the existing Material layouts and does not initialize or wrap the package.
- `_IOSLiquidGlassHome` in `lib/ui/flux_news_body.dart` owns the shared `GlassLargeTitleController`, temporarily exposes its `ScrollController` through `FluxNewsState` so existing jump/list-position behavior still works, and restores the previous controller when disposed.
- iPhone uses a fixed transparent `GlassAppBar`, collapsing `GlassLargeTitle`, and a floating `GlassContainer` behind only the compact title/count. Its actions live in a centered floating bottom group: Sync/abort is fixed first, up to three configured direct actions follow, and More is fixed last. The top app bar does not duplicate these actions. Wide iPad layouts use an adaptive 260–340pt leading sidebar and a trailing news pane; compact/large titles, top actions, download progress, and the mini player align to the news pane. The compact iPad title container is intrinsically sized and left-aligned rather than stretched across its pane.
- The wide iPad sidebar is one full-height floating standard/frosted Glass surface with a stable high-contrast recipe, even when Clear Glass is enabled for compact controls. In OLED/True Dark Mode its dedicated recipe switches to a pure-black backer and subdued black Glass tint while retaining a restrained rim/depth response; normal Dark Mode keeps the raised charcoal appearance. Its Flux News header icon/title use the shared roomier 20pt horizontal, 24pt top, and 16pt bottom inset; unselected category/feed rows inherit the same theme foreground, while the active row receives a flat translucent accent selection. Category/feed rows remain plain children rather than nested Glass surfaces. At widths below 800pt, including iPhone and narrow iPad Split View, the permanent sidebar becomes an inset, rounded Liquid Glass overlay using the same sidebar recipe and header spacing. Full-width 10.5-inch iPad portrait layouts at 834pt therefore keep the permanent sidebar. Flutter's underlying Drawer route is retained so the leading-edge swipe, scrim, accessibility/back behavior, and close-after-selection behavior remain intact. Android continues to use its Material Drawer. News cards remain opaque content surfaces in both iOS variants.
- Wide-iPad sidebar top-level rows use the same explicit 8pt leading/16pt trailing tile inset and a fixed 32pt right-aligned count slot. This keeps All News, Bookmarks, and expandable category counts on the same trailing edge despite their different `ListTile` and `ExpansionTile` implementations.
- The same persistent navigation selection treatment is shared by the compact iOS overlay sidebar, Android Drawer, and fixed Android tablet sidebar: a rounded 14%-opacity accent fill plus accent-colored icon/title/count. iOS resolves system blue while Android resolves the configured Material color-scheme primary; both compact and permanent iOS sidebars opt into the denser 44pt row metrics.
- Category navigation owns one `ExpansibleController` per category. The category containing the currently selected feed starts expanded and is also expanded when a programmatic feed change moves selection into it; the selected feed keeps its existing accent highlight. Other categories retain their user-controlled expansion state.
- The Apple toolbar action selection is shared by iPhone, compact iPad, and wide iPad through General Settings. Sync/abort is always the first fixed action; Search, the contextual All/Unread switch, sort direction, current-scope Mark as Read, Mark as Read and Next, Podcasts, and Settings can be enabled and drag-reordered. Mark as Read and Next is available only while a feed or category is selected. The persisted selected list `iosToolbarActions` and complete order `iosToolbarActionOrder` are independent from Android, and the saved order is the display priority. iPhone and compact iPad show up to the first three applicable selected actions directly; every other applicable action remains in More. Wide iPad shows every applicable selected action that fits; More disappears only when all currently applicable actions are selected and fit beside the reserved title area. The default selection is Mark as Read.
- iPhone bottom chrome stacks download progress, audio mini-player, then the floating action group without duplicating the bottom safe-area inset. Compact and wide iPad place the equivalent group at the top of the news pane. The fixed Sync location invokes the same sync/abort callback in every Apple layout. The former independent iPhone Mark-as-read and Sync switches are no longer shown; the obsolete Sync quick-action state/key/localization has been removed, while the legacy Mark-as-read key remains only as an input for migration.
- After a successful manual sync from an Apple toolbar, list reset uses the shared `GlassLargeTitleController` scroll extent rather than `SuperSliverList.jumpToItem(0)`. This fully expands the large title/count and places the first news card below them. Aborted or failed syncs do not use this Liquid-Glass-specific success callback.
- Successful startup syncs, including the first sync entered through Feed Onboarding, use the same iOS result. `FluxNewsState.resetListToStart()` waits until both the replacement news list and scroll controller are attached, then jumps the shared controller to its minimum extent on iOS; Android retains the first-item `SuperSliverList` reset. Manual sync and navigation resets reuse this routine so an early frame cannot silently leave the title collapsed.
- Regular configured iPad app starts also use `resetListToStart(revealIOSLargeTitle: true)` after the first frame instead of restoring a list index. Even an index-0 item jump aligns the first card to the top and collapses the title, so iPad intentionally starts with the first card below the fully expanded Large Title in both portrait and landscape. When a `GlassLargeTitleController` is present it takes precedence over the generic tablet top spacer; Android tablets without that controller retain the standalone inset. This keeps the visible expanded iPad title and compact-title transition coupled to the same controller. iPhone and Android retain their existing saved-position restoration.
- The iOS More-menu toggles for All/Unread and Newest/Oldest use the same expanded-title list reset after their replacement query completes. They therefore return to the first card below the fully expanded title instead of aligning that card against the top edge. Android retains its existing `jumpToItem(0)` menu behavior.
- Selecting All News, Bookmarked, a category, or a feed from the drawer/sidebar uses the same expanded-title reset after the selected database query completes. Android retains its existing `SuperSliverList.jumpToItem(0)` behavior for these navigation changes.
- The dedicated Search route now has its own iOS Liquid Glass shell: a transparent `GlassAppBar`, standalone glass back button, and `GlassSearchBar` using the persisted Clear/High-Contrast recipe. The field autofocuses on entry, submits only through the keyboard search action, and its built-in clear action also clears the result list. Results receive a safe-area-aware top inset so the first card starts below the floating controls while scrolled cards can pass behind them. Android retains the previous Material AppBar/TextField search layout.
- Search results reuse the existing `NewsCardIOS`/`NewsRowIOS` selection and therefore the same `NewsGlassContextMenu` as the main view; no search-specific context-menu implementation is required.
- Settings Liquid Glass steps 1-6 are implemented through `AdaptiveSettingsScaffold` and the Flux News-owned controls in `lib/ui/settings/adaptive_settings_controls.dart`. Android retains its Material AppBar and Material controls, and the shared Android scaffold wraps every settings body in an explicit bottom `SafeArea` with `maintainBottomViewPadding`, so scrollable content continues to use the persistent `viewPadding.bottom` and ends above gesture and three-button system navigation even when an edge-to-edge ancestor has consumed regular padding, including on tablets. On iOS, every Settings page opens with a fully expanded `GlassLargeTitle` and collapses into the floating compact glass title while its own content scrolls. The root content is separated into Miniflux, Settings, Debug, and Backup groups, while every dedicated settings page places its controls in at least one matching `AdaptiveSettingsGroup`; the reorderable toolbar list uses the same surface directly. iOS uses non-glass system grouped surfaces and Android uses rounded Material `surfaceContainerLow` groups. Internal dividers start at the 16pt leading icon inset instead of after the icon/text gap and use an 8pt vertical extent on both platforms so adjacent rows do not feel compressed. Internal page destinations in the overview and the Android floating-action configurator use the shared `AdaptiveSettingsNavigationRow`, giving them the same icon/title spacing as switch/dropdown rows while retaining a full-width InkWell, platform-aware minimum height, semantics, optional subtitles, and a trailing chevron. Dialog actions, immediate commands, and external links keep their purpose-specific controls. In normal Dark Mode the group surfaces retain their raised system gray; when OLED/True Dark Mode is active they resolve to pure black. Settings groups remain capped to the shared `adaptiveSettingsMaximumContentWidth` of 720pt on wider layouts.
- Settings step 4 — adaptive controls: switches use `GlassSwitch`, form inputs use `GlassTextField`, and dropdown selections use an anchored, screen-adjusting `GlassMenu` with a checkmark on the current value. All shared iOS Settings text fields default to the dedicated flat `iosLiquidGlassInputSettings` recipe (zero shadow and reduced glow/rim/chromatic response) instead of the button-like general control recipe; explicit per-field overrides remain possible. `GlassPicker.showSheet()` in package `0.29.2` is intentionally not used because it does not commit/return its selected item. Long or numerous menu values are clamped to the safe screen area and scroll when required. Visible scrolling controls explicitly use `GlassQuality.standard` with the persisted Clear/High-Contrast recipe. Radio lists use Flutter's adaptive constructor. Header Settings now owns stable text controllers outside `build()`, and Feed Settings has a dedicated controller separate from the global news-search controller. Disabled states and semantics remain represented by the Flux News facade.
- Settings step 5 — dialogs and actions: URL/API-key editing, local-cache deletion, downloaded-audio deletion, and backup password/encryption prompts now use `GlassDialog` with glass actions and standard-quality shared-layer fields/switches on iOS. Android keeps its existing `AlertDialog` and Material actions. Destructive actions retain destructive styling, passwords remain masked, and the existing validation and asynchronous credential/deletion flows are unchanged. System-owned share/about sheets remain native.
- Main-view dialogs now share the Flux News-owned `showAdaptiveGlassDialog` facade: mark-all-as-read confirmation, general errors, long-sync warnings, too-many-news warnings (including Search), and downloaded-podcast item deletion use `GlassDialog` with the persisted Clear/High-Contrast menu recipe on iOS. Android retains the previous Material `AlertDialog` paths. Bulk-read database updates, optional immediate Miniflux synchronization, counters, and list refresh behavior remain unchanged.
- Settings step 6 — special screens: `DownloadStorageSettings` and `LogViewerScreen` now use `AdaptiveSettingsScaffold`, the same large-to-compact title behavior and 720pt iOS content cap. Download summary cards and log rows remain standard content surfaces. The Log Viewer adds glass refresh/clear actions, a glass search field, and a controlled glass level picker on iOS; Android retains its existing refresh/clear buttons, text field, and filter chips. Automated verification completed with scoped `flutter analyze lib test`, the full Flutter test suite, and focused Settings/config/Liquid-Glass tests. Manual Light/Dark, Clear/High Contrast, Reduce Transparency, increased contrast, large text, rotation/iPad, keyboard, pull-to-refresh, and performance checks remain required on simulator/real devices.
- `NewsGlassContextMenu` replaces only the iOS context-menu preference branch in both card and row layouts. One adaptive Glass menu contains bookmark, read/unread, open, share, Open in Miniflux, supported third-party save, comments, and audio download where applicable. There is no secondary action sheet. The real card remains rendered beneath a transparent full-card menu trigger while the package hides that trigger during its morph, so opening the menu no longer leaves a confusing empty list slot. State-mutating actions run after the menu close animation. `openNewsAction` captures all context-derived dependencies before changing read state: the ensuing list refresh may replace the source card even when read articles remain visible. URL launch therefore no longer depends on that card still being mounted, and the secondary widget-snapshot refresh runs without delaying or cancelling article navigation. Optional removal of read articles remains a separate list-setting behavior.
- Podcast playback now has an iOS-specific Liquid Glass presentation while preserving the existing Android Material player and all shared playback/persistence logic. `PersistentAudioMiniPlayer` renders as a floating standalone glass superellipse above the bottom toolbar with title/feed, -30 seconds, Play/Pause, +30 seconds, Stop, progress, and tap-through to the full player. `NewsAudioPlayerScreen` uses a transparent `GlassAppBar`; its Material content cards remain non-glass, while progress/speed use `GlassSlider`, sleep and interval controls reuse the adaptive Settings controls, download/details actions use standalone glass buttons, and rewind/play/stop/forward/reset share one lightweight `GlassButtonGroup`. Interactive glass controls are deliberately not nested in a `GlassCard`, matching the package's glass-in-glass restriction and limiting additional rendering cost to fixed control surfaces. The shared Android/iOS chapter list renders each active-row background on a row-local `Material` inside an explicitly clipped `ListView`; do not move the highlight back to `ListTile.tileColor` on the surrounding player Card, because ancestor Ink painting remains visible beneath the fixed Chapters header after the row text has scrolled out. Chapter rows and the automatic offset calculation share the fixed 56pt `_chapterTileExtent`; the dense `ListTile` default is only 48pt and previously caused cumulative overscroll. A directly tapped chapter is marked as already positioned before seeking so its subsequent playback-state update does not move the visible row, while automatic chapter changes during uninterrupted playback continue to scroll into view.
- Active podcast downloads in the main bottom chrome now use one floating iOS Glass superellipse with `GlassQuality.standard`; the live progress rows and cancel buttons remain plain children so frequent stream updates do not create nested shader surfaces. `DownloadsOverview` uses the shared collapsing `AdaptiveSettingsScaffold` navigation on iOS while its summary and episode cards remain normal content surfaces. Its centered content is capped to the same shared 720pt maximum on iPad and Android tablets. Android preserves the original full-width Material download banner and AppBar.
- The remaining pre-content iOS routes are also covered: Welcome keeps its plain brand/logo content while Login and Restore are standalone Glass actions; Login is prominent and blue-tinted, Restore is neutral, and the iPad layout has no enclosing Material/Glass action card. Login uses collapsing large-title navigation, validated `GlassTextField` credential inputs with a dedicated flat/no-shadow Glass recipe, and standalone Glass actions. Its custom-header editor is collapsed by default, explicitly marked optional, and automatically expanded when stored headers exist on both iOS and Android; Android uses a Material `InkWell` disclosure row while retaining its existing form controls. Feed Onboarding uses the same collapsing large-title navigation plus Glass select/clear/save actions. Category and feed content intentionally remains non-glass, but iOS uses flat grouped surfaces and `CupertinoListTile` selection rows with animated circular checkmarks instead of elevated Material cards and square Material checkboxes. Restore Settings starts with a large title, presents its file guidance as a plain secondary empty state rather than a button-like card, and uses the shared Glass confirmation/password-dialog path. Android retains the existing Material forms, buttons, navigation and dialogs.
- The old iOS FAB/Mark-as-read quick-action intent is migrated once and idempotently into `iosToolbarActions`: only an explicitly visible Mark-as-read FAB enables that action, while a fresh configuration defaults to Mark as Read. The shared toolbar settings destination is shown on iOS; legacy FAB/glass/AppBar controls remain available only on Android.
- Verification completed during implementation: scoped analyzer passed for all changed Dart/test files, `test/config_read_test.dart` passed including legacy-FAB mapping cases, and an iOS simulator debug build completed successfully. Remaining manual checks are listed below.
- The evaluated baseline dependency is `liquid_glass_widgets` `0.29.2`. Pin the exact version initially rather than using a caret constraint, because the pre-1.0 package has frequent releases and recent breaking API changes. Recheck the current package version, changelog, open issues, Flutter requirements, and license immediately before implementation. `native_liquid_glass` is not the selected option.
- `liquid_glass_widgets` is a Flutter shader/`BackdropFilter` approximation and does not call Apple's native iOS 26 Liquid Glass APIs. Its interaction structure can therefore run on every Flux News-supported iOS version. The app currently targets iOS 17.0.
- Package boundary is strict: package initialization, wrapping, and `liquid_glass_widgets` widgets remain selected only by the iOS app path. Android's optional floating-chrome layout uses Flutter Material widgets plus a tightly clipped core `BackdropFilter`; it does not initialize or render the Liquid Glass package. Android card long-press behavior and settings controls remain Material. The dependency's assets may still affect Android artifact size, so compare release APK/AAB sizes after dependency changes.
- All iOS versions from 17 onward use the same new interaction layout even if the high-quality visual effect is unavailable. Rendering quality may degrade, but button positions, actions, semantics, sizes, and navigation must not revert to the old iOS AppBar/FAB arrangement.
- Use `GlassQuality.standard` explicitly for the initial production implementation, including the floating compact title and individual controls. Do not enable the package's experimental adaptive-quality benchmark initially. If shader filters are unavailable or rendering fails, retain the same layout with the package's shader-free `minimal`/frosted `BackdropFilter` fallback. A more opaque surface is the final accessibility/safety fallback. Premium quality may be evaluated later only for fixed chrome on profiled modern devices.
- Floating iOS chrome uses theme-specific readability settings with `blur: 16`: Dark Mode keeps a 35% neutral dark backer with white foregrounds; Light Mode uses a translucent white backer, stronger ambient rim/Fresnel highlight and shadow, with black foregrounds. Compact title/count and action icons therefore remain legible over detailed article images without restoring a full-width bar surface.
- General settings expose a persisted iOS-only `Use Clear Liquid Glass` switch. Off keeps the original high-contrast `blur: 16` recipes and `GlassQuality.standard`; on selects a visibly clearer `blur: 4` recipe with lighter backers and `GlassQuality.premium` for stronger refraction/rim rendering. The package adaptively falls back when Premium is unavailable. The selected recipe and quality are shared by top chrome, bottom controls and menus; Android remains unchanged.
- Expanded menus use a denser theme-specific Glass recipe than the compact controls (`blur: 14` plus a neutral 70% tint in Clear mode), because their larger text surface can span several high-detail article images. The More menu is screen-adaptively up to 340pt wide and permits two-line, 56pt-high items so localized action names are not truncated.
- Keep the package behind Flux News-owned widgets/facades so package API churn or a kill switch does not leak throughout the app. Suggested boundaries are `FluxNewsAdaptiveScaffold`, `FluxNewsTopChrome`, `FluxNewsBottomChrome`, and `NewsGlassContextMenu`; exact names may change during implementation. Avoid replacing the whole app with `GlassScaffold`, because the current Material `Scaffold` owns the Drawer, bottom banners, layout behavior, and Android path.

### iPhone layout

- The iPhone shell uses a transparent fixed `GlassAppBar` plus `GlassLargeTitle` as the first list sliver. A shared `GlassLargeTitleController` owns the list `ScrollController` and drives the cross-fade.
- At the top of the list, show the selected feed/category as the large title. When the existing AppBar-count preference is enabled, the article count appears as secondary plain text beside the large title and remains visible beside the compact title. During scroll, the large title fades/collapses and the compact title/count fades into a small independent `GlassContainer` in the fixed 44-point top bar. The top bar itself remains visible and otherwise transparent.
- The expanded article count is rendered as localized secondary metadata directly below the large title (`1 Nachricht` / `n Nachrichten`) rather than as a detached trailing number. It shares the large title's fade curve, which keeps long and multi-line feed names visually balanced. The compact title retains the short inline numeric count to conserve space.
- In a single-pane portrait window, the top bar contains only the leading feed/category Drawer button and compact selected title/count. In a single-pane landscape window, the same configurable compact action group used by a narrow iPad moves into the top-right of the Glass AppBar; the bottom action group is omitted. This decision follows the current pane's `width > height` and therefore also adapts to iPhone rotation, Split View-style resizing, and foldable sub-screens without relying on a physical-device label.
- Extend list content beneath the transparent top chrome and route the news pane through the Flux News-owned `IOSNewsScrollEdgeEffect` facade. It currently delegates to the package's `GlassScrollEdgeEffect` with the native-like `soft` style, an explicitly calculated status-safe-area plus 44-point navigation height, a 25-point transition extent, and the current scaffold background fallback. This avoids duplicating Scaffold media padding and provides one replacement boundary for a future iOS-native `UIScrollEdgeEffect` implementation. On wide iPad layouts it affects only the news pane, not the persistent Glass sidebar. Keep the compact title's own blurred glass surface for local title legibility. Add a scrollable initial top inset so the expanded large title starts below the status/navigation area. Handle populated, loading, null/empty, error-dialog-background, long-sync, too-many-news, portrait-card, and landscape-row states consistently; none may accidentally receive two AppBars or lose required top/bottom spacing.
- The centered bottom action group contains fixed Sync/abort first, up to three configured applicable actions, and fixed More last. Configured overflow and unselected applicable actions remain in More; Mark as Read and Next is omitted outside feed/category scope.
- In portrait, bottom chrome stacks the current `PersistentDownloadBanner`, `PersistentAudioMiniPlayer`, and action group in that order and applies the bottom safe area only once. The news sliver consumes the dynamic bottom padding supplied by the extended `Scaffold`, so the final card can travel behind and then fully past the floating toolbar even when download/player banners change its height. In compact landscape only the banners remain at the bottom and the news list retains a scrollable system-navigation inset. `IOSNewsScrollEdgeEffect` now receives the explicit presence of bottom action controls instead of inferring it from the device class: its bottom soft edge effect and shared 25-point transition are enabled only for the portrait iPhone action group. Compact-landscape iPhones and all iPads omit the bottom effect because their actions are at the top.
- Sync retains existing behavior: normal tap starts sync, the control shows adaptive progress while syncing, and tapping during a long-running sync preserves the current abort behavior. Refresh and progress states share a fixed 24pt icon slot, so neither the iPhone bottom action group nor the compact/wide iPad top toolbar changes size when sync starts or ends.
- The configured Mark as Read control keeps its context-sensitive all-news/bookmarks/category/feed label and existing confirmation flow. The separate Mark as Read and Next action is immediate and appears only for feed/category scope.

### iPad layout

- Preserve the two-pane information architecture on iPad widths of at least 800pt: a fixed 260–340pt category/feed sidebar on the leading side and flexible news content on the trailing side. This leaves at least about 540pt for the news pane at the breakpoint. Below it, replace the permanent sidebar with the temporary Liquid Glass overlay sidebar so narrow Split View retains useful reading width.
- Render the permanent sidebar as one floating `GlassContainer` using `GlassQuality.standard` and a dedicated frosted/high-contrast recipe. Do not inherit Clear/Premium quality for this large surface, and do not nest Glass shaders in rows. Selected categories/feeds use a flat translucent iOS accent fill; content cards remain opaque.
- Apply the collapsing large title to the news-content pane. Both compact and wide iPad toolbars place fixed Sync/abort first, then configured applicable actions, then conditional More. Compact iPad shows up to three direct actions; wide iPad calculates capacity from the news-pane width. Download progress and the mini player remain at the bottom of the content pane. iPhone places the equivalent configurable group at the bottom for one-handed use.
- Test both orientations, Split View widths around the 800pt breakpoint, supported Dynamic Type sizes, long category/feed names, Light/Dark Mode, Clear/High Contrast controls, and sidebar scroll performance.

### iOS settings and migration

- iOS no longer uses an FAB. Android retains the current optional FAB and its selectable Sync/Mark-as-read action.
- iOS exposes one shared drag-reorderable action configuration for the iPhone bottom toolbar and both iPad top-toolbar variants. The former independent quick-action rows are removed; Sync is fixed and Mark as Read is one of the selectable actions. iOS does not expose the old AppBar-style, FAB, glass-FAB, or FAB-action settings.
- Migration rule for existing iOS installs: a stored quick-action preference takes priority; otherwise an enabled FAB configured for Mark as Read enables that action, while an explicitly hidden or Sync-configured FAB leaves it disabled. A fresh configuration defaults to Mark as Read. Persist the result under the shared `iosToolbarActions`/`iosToolbarActionOrder` keys so migration is idempotent and Android semantics remain unchanged.

### News-card context actions

- Preserve the existing three long-press preference modes: `expand` continues to expand/mark the item as today, `none` remains without a long-press action, and only the context-menu mode replaces `CupertinoContextMenu.builder` in `NewsCardIOS` and `NewsRowIOS`.
- Replace the lifted, enlarged, internally scrollable Cupertino card preview with a Flux News-owned `NewsGlassContextMenu` built around `GlassMenu` and `GlassMenuController`. Keep the card stationary; open the menu from long-press with haptic feedback, `morphFromZero: true`, `autoAdjustToScreen: true`, safe screen-edge padding, `GlassQuality.standard`, tap-outside dismissal, and an accessible non-gesture invocation path.
- Keep all applicable card actions in one adaptive, screen-clamped Glass menu: Mark as read/unread, Add/remove bookmark, Open article, Share, Open in Miniflux, save to the configured third-party service when supported, open comments when present, and download audio when present. Use two-line items where needed and allow the menu to scroll only when screen height or Dynamic Type requires it.
- Extract per-news action descriptors/callbacks from the duplicated Material and Cupertino menu builders so Android and iOS use one action policy while retaining platform-specific presentation. Preserve current capability checks, localization, read/list removal behavior, counter refreshes, widget snapshot updates, sharing origin requirements, and audio handling.
- Actions that can remove the anchor card from the current list must first dismiss and fully settle the menu, then mutate state/remove the item. Do not unmount the menu anchor during its close animation.

### Verification and acceptance criteria

- Automated coverage includes adaptive breakpoints, iPhone/compact-iPad three-action priority, wide-iPad capacity/overflow, feed/category-only Mark as Read and Next availability, Android direct-action/More parity, selection persistence, and legacy iOS Mark-as-read migration. Run scoped `flutter analyze lib test` and the complete Flutter test suite after toolbar changes.
- Manually test light/dark mode, high contrast, Reduce Motion, large Dynamic Type, portrait/landscape, short and long lists, overscroll, active downloads, active audio, sync abort, and remove-read-items behavior on real iPhone/iPad devices spanning the oldest supported iOS/device class and a current iOS 26 device. Profile scroll/raster performance with `GlassQuality.standard` and verify the minimal/frosted fallback explicitly.
- Acceptance requires identical action ordering (`Sync`, configured direct actions, conditional `More`) across Apple layouts, no duplicate iOS Sync/FAB controls, no obscured final news item, no context-menu anchor crashes, and no behavioral or visual regression in Android's AppBar, Drawer, intentionally retained legacy FAB long-press, card menu, or tablet layout.
